Introduction

HoneyBan is an open source firewall that blocks bad traffic at the kernel level using eBPF and XDP. It is an alternative to fail2ban and UFW, with significantly higher throughput and lower CPU usage.

  • eBPF + XDP: packet filtering in the kernel
  • ~10× faster than traditional userspace tools
  • No kernel modules to compile; uses built-in eBPF support

Requirements

  • Linux kernel 5.4+ (eBPF/XDP support)
  • Root or CAP_NET_ADMIN for loading eBPF programs
  • Supported NIC driver for XDP (native or generic)

Installation

Clone the repository and build (or use pre-built binaries when available):

git clone https://github.com/AzizbekGolden/honeyban.git
cd honeyban
make
sudo make install

Or with your package manager once packages are published.

Configuration

Configuration is typically in /etc/honeyban/config.yaml (or similar). Example:

# Block list: IPs or CIDRs to drop
block:
  - 192.0.2.0/24
  - 203.0.113.42

# Interface for XDP
interface: eth0

# Log level: debug, info, warn, error
log_level: info

Start the daemon:

sudo honeyban --config /etc/honeyban/config.yaml

Exact options and paths depend on the released HoneyBan daemon. See the GitHub repo for up-to-date instructions.

eBPF & XDP

XDP (eXpress Data Path) runs a program as soon as a packet is received by the NIC driver, before it enters the kernel network stack. You can drop, pass, or redirect packets with minimal overhead.

eBPF is the in-kernel VM that runs these programs. The kernel verifies eBPF bytecode for safety, so you don't load arbitrary kernel modules.

HoneyBan uses eBPF programs attached at the XDP hook to match source IPs against a block list and drop matching packets before they consume more CPU.

Comparison with fail2ban / UFW

Aspect HoneyBan fail2ban / UFW
Where blocking happens Kernel (XDP) Userspace / iptables/nftables
Performance Very high (early drop) Good, more CPU per packet
Dynamic rules Yes (via daemon) Yes (fail2ban) / static (UFW)

Same goal—block bad IPs and protect services. HoneyBan focuses on maximum throughput and kernel-level control.
